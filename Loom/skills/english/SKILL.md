# English Learning Augmenter

当用户问英语问题时，**不能**直接给出英语答案——必须先检索知识库，用用户已有知识辅助理解，再记录学习痕迹。

## 核心理念

> 语言学习的最优路径是用已知解释未知。用户的 Vault 中已经积累了 AI、数学、物理、计算机等领域笔记——这些是英语学习的"锚点"。

## 会话复用规则

在日常对话中（无论英语技能是否被触发），Agent 应主动复用用户已学过的英语表达：

1. **加载学习记录**：会话开始时，扫描 `Loom/wiki/english-data/expressions/` 和 `Loom/wiki/english-data/tech-english/` 下最近 3 天的文件，提取已记录的英语表达清单
2. **自然穿插**：在正常中文对话中，恰当时机用英语替换中文词（如"这个参数需要 fine-tune 一下"），优先选择最近学过的表达
3. **克制原则**：每轮对话最多穿插 1-2 个英语表达，不刻意不堆砌，以自然为第一优先级
4. **首次标注**：会话中第一次复用时，用括号简短标注中文含义（如"这是个 trade-off（权衡）"），后续复用不再标注
5. **不重复提醒**：用户已经熟练使用的表达（连续 3 次对话中自然使用且正确），从复用清单中降权

**禁忌**：不要因为这条规则把中文对话变成中英混杂。复用是调味料，不是主菜。

## 四阶段工作流

### 阶段一：理解问题 & 提取关键概念

解析用户的问题，提炼出：
- 要学习的英语表达/用法/词汇
- 涉及的领域/场景
- 用户的意图（口语/写作/学术/技术）

### 阶段二：检索知识库锚点（核心）

根据阶段一提取的领域/场景，在 Vault 知识域中搜索关联笔记：

| 领域信号 | 搜索路径 | 示例 |
|:---|:---|:---|
| AI/深度学习/大模型 | `Vault/notes/人工智能 AI/` | 用户问"gradient descent" → 找 AI 笔记中的梯度下降 |
| 数学/微积分/线性代数 | `Vault/notes/数学 Math/` | 用户问"convergence" → 找微积分笔记中的收敛 |
| 物理/力学/电磁学 | `Vault/notes/物理 Physics/` | 用户问"momentum" → 找物理笔记中的动量 |
| 编程/算法/系统 | `Vault/notes/计算机 Computer/` | 用户问"abstraction" → 找计算机中的抽象层 |
| 工程/设计/制造 | `Vault/notes/工程 Engineer/` | 用户问"tolerance" → 找工程中的公差概念 |

**检索方法**：
1. 先用 `search_file` 的 query 模式搜索 `Vault/notes/` 下相关笔记（匹配文件名和正文）
2. 再用 `read_file` 读取最相关的 1-3 个文件，提取用户已知的概念和术语
3. 将已知概念作为"类比锚点"，准备用它们解释新的英语表达

**锚点判定依据**：笔记中已经包含该概念的中文名称、定义、使用场景——说明用户已掌握，可以作为类比材料。

### 阶段三：生成关联解释

用锚点知识辅助给出英语表达的解释，必须包含：

```
【你要的表达】<英语>  /音标/
【字面意思】<直译>
【你的知识锚点】来自 [[notes/.../xxx]] 中的 <已知概念>
【类比理解】用已知概念类比新表达：在 <已知概念> 中，<类比关系>；同理，<新表达> 中，<解释>
【使用场景】<什么时候用、什么语境>
【搭配/变形】<常见搭配、同义替换>
```

**类比原则**：
- 优先用用户笔记中**最近学过的概念**（从 hot.md 和文件修改时间推断）
- 跨学科类比优先（如用物理动量解释英语 momentum）
- 禁止生造不存在于用户笔记中的"已知知识"

### 阶段四：记录学习痕迹

将本次学习内容写入 `Loom/wiki/english-data/` 对应子目录：

| 内容类型 | 写入位置 | 格式 |
|:---|:---|:---|
| 单词/短语/表达 | `Loom/wiki/english-data/expressions/<YYYY-MM-DD>.md` | 追加式，新条目在顶部 |
| 技术英语/学术表达 | `Loom/wiki/english-data/tech-english/<YYYY-MM-DD>.md` | 追加式 |
| 语法点/用法辨析 | `Loom/wiki/english-data/grammar/<YYYY-MM-DD>.md` | 追加式 |
| 每日学习日志 | `Loom/wiki/english-data/daily-notes/<YYYY-MM-DD>.md` | 追加式流水 |

**写入格式模板**：

```markdown
## <英语表达>

- **日期**: YYYY-MM-DD
- **锚点**: [[notes/.../xxx]] 中的 <概念>
- **类比**: <一句话类比关系>
- **例句**: <带上下文的例句>
- **标签**: #vocabulary #tech #grammar
```

## 触发词

用户说以下表达时加载本技能：
- "这个用英语怎么说"
- "XXX 英语表达"
- "英文怎么说"
- "翻译成英语/英文"
- "英语学习" + 具体内容
- "教我 XX 用英语"
- 直接用英语提问某个表达的含义（如"'serendipity' 是什么意思"）

## 阶段五：同步语料本

语料本位于 `Vault/notes/语言 Language/natural language/`，两个文件，无总站：

| 文件 | 内容 |
|------|------|
| `Words.md` | 单词、固定搭配、短语 |
| `Patterns.md` | 句式模板，语法要点内嵌其中 |

每次在 Loom 侧记录新表达后，**必须**同步写入对应文件。

**写入格式**：

```
## <英文词/句式>

/<音标>/  (<词性>) <中文释义>。

<英文详细释义>。

- <例句>（<翻译>）

参见 [[...]]（有自然关联时添加）

<日期>
```

**硬约束**：禁止元标签、AIGC 声明、维护说明。一条内容最多一例句，日期放末尾。

## 阶段六：自动清理

定期扫描用户 journal（`Vault/journal/`）中近期日记，检查语料本中的词汇/句型是否已被用户自然使用：

1. 搜索 journal 中最近 14 天的 `.md` 文件，匹配语料本中的每个条目
2. 某条目在日记中自然出现 **≥3 次**（非引用、非解释该词本身），判定为「已掌握」
3. 从语料本对应文件中移除该条目
4. 移除后不通知用户——语料本的安静消失本身就是信号

## 使用说明

Main Agent 加载本 skill 后，应：
1. 先走四阶段流程，不可跳过阶段二（知识库检索）
2. 检索到锚点才能给出解释；若用户知识库中无相关锚点，如实告知并建议「先建相关领域笔记」
3. 阶段三的解释输出必须包含锚点引用（用 [[wikilinks]] 格式）
4. 阶段四的记录写入后，用 `yyb-product` 声明写入的文件
5. 阶段四之后必须执行阶段五，将新表达同步到 Vault 侧入口
6. 同一会话中多次英语问答，不必重复检索同一领域（缓存已知锚点）
