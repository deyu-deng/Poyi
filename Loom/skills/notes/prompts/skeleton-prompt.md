# 知识骨架生成提示词

将以下内容整理为一份**知识骨架笔记**，用于建立底层逻辑框架。

## 角色

学科助教。擅长把复杂知识拆成层层递进的逻辑链条。目标不是罗列细节，而是让读者理解"这个概念为什么会出现""它解决什么问题""它和前面的知识怎么连起来的"。

**风格要求**：简洁直接，信息密度高。参考 [ch12.md](https://github.com/...) 的写法——不拖泥带水，每个词都有信息量。

## 输入材料

[在此处粘贴你的教材章节、讲义、或网页内容]

## 输出要求

### 1. 组织顺序

按教材原有章节顺序组织，不要打乱。可以在小节内部按"定义 → 性质 → 定理 → 应用"的逻辑微调，但大节顺序与教材保持一致。

### 2. 标题层级（严禁跳级）

```
# 第N章 [标题]（第一轨：知识骨架）    # 章级
## [N].[M] [小节标题]                  # 节级
### [概念/定理名称]                     # 概念级
#### [细节标签]                         # 细节级（典型示例、易混淆点等）
```

### 3. 每个核心概念必须包含

按这个顺序组织：

```
### [概念/定理名称]

**核心内容**：[定义、定律、模型、公式——根据学科特性自然呈现]

**直观意义**：[一句话解释，可用类比但须书面化严谨，禁止网络化口语如"死死地""脚踏两只船"]

**条件/前提**：[适用范围、假设、理想化条件——缺了就会错]

**证明思路**：[关键步骤，不需要完整细节]
- [步骤1]
- [步骤2]

**与前文的联系**：[依赖关系或推广关系。使用"与前文的联系"而非"连结"]

#### 典型示例（辅助理解）

**示例**：[一道典型且有一定难度的题，不是简单套公式。使用"示例"而非"例题"]

**思路**（不写完整计算）：
- 识别：这是什么类型的问题
- 方法：对应哪个定理/公式
- 验证：结果应该满足什么特征

> 完整计算见教材/习题册
```

### 4. 章末必备

- **易混淆点**：用表格对比（如有）
- **本章逻辑链条总览**：ASCII 树形图或箭头图串起所有概念
- **必须默写的核心公式**：编号列表（如有）

### 5. 格式

- Markdown 大纲，层级用 `#` / `##` / `###` / `-`
- **所有公式用单行 `$...$` 包裹，不要用 `$$...$$`**
- 表格控制列数（≤4列），太复杂则转为列表

### 6. 控制（禁止输出）

- 完整计算过程
- 解题技巧（那是第二轨的事）
- "值得注意的是""让我们来看看"等过渡语
- 改变原始知识含义的内容
